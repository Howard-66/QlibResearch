## 价格突破策略的机器学习解决方案
### 为什么需要 ML
**逻辑规则能告诉你"够不够"，ML 能告诉你"谁更好"**
一个选股策略筛选完可能还剩 15 只候选。它们都是"合格"的——但哪几只更值得买？
- **❌ 纯逻辑规则的局限**
    - 结果是二元的——通过或不通过，没有"程度"
    - 15 只通过了的股票全是一个等级
    - "灰度信息"全丢了——盘整了多久？均线收敛多紧？量价关系怎样？
    - 规则是人写的，只能覆盖你想到的因素
    - 不同条件之间的交互效应，人工无法穷举

- **✅ ML 带来的增强**
    - 输出连续评分——每只股票一个预期收益率数值
    - 从历史几万个突破事件中学习规律
    - 70+ 特征同时考虑——量价形态、均线关系、市场环境、基本面
    - 自动发现交互——"高换手+低波动=好信号"这类组合
    - 结果可排序——优先关注排名靠前的

💡 **ML 不是替代选股规则，而是在规则筛选出的候选池里"优中选优"。这个顺序不能反。**

### 训练管道
**从历史数据到可部署模型：四步闭环**
每一步都只用到当时已知的信息——整个管道不存在未来函数。

**四步闭环流程：**
1. **数据采集**
    - 对每个历史交易日
    - 运行选股策略
    - 记录候选 + 后续走势
2. **自动标注**
    - 突破后13天收盘 ≥ 突破日最高 × 1.03
    - → label = 真突破
3. **特征提取**
    - 对每次突破事件
    - 从250天K线中
    - 提取 ~70 个特征
4. **模型训练**
    - LightGBM 回归
    - 预测 future_return
    - 保存模型供评分调用
        
**标注策略的讲究**
为什么用13天而不是10天？因为给了**3天回踩宽限期**。很多真突破在第10天恰好处于回踩最低点，如果按10天标注会被错判为"假突破"。13天的窗口让"延迟成功"的股票得到公正评价。

**数据划分的讲究**
**必须用时间分割，不能用随机分割。** 训练集到 2025-08，验证集到 2026-01，测试集在之后。随机分割会导致同一只股票的不同突破事件分散在不同集合——模型会"记住"这只股票的股性，造成隐式数据泄露。

### 特征工程
**70 个特征 • 九大类：把你的"看图经验"翻译成数学**
你面对一只突破前高的K线图会看什么？特征工程就是把你看的东西变成可计算的数字。
- **① 突破强度（8个）：** 振幅 • 实体占比 • 上影线 • 涨幅 • ATR比率 • 量比
- **② 前高形态（6个）：** 距今交易日 • 高度 • 前高量比 • 回撤 • 触碰次数
- **③ 盘整蓄力（12个）：** 5~30天波动率 • 紧密度 • 量能趋势 • 缩量 • 均线收敛
- **④ 量价关系（9个）：** 量价相关 • OBV背离 • MFI • VWAP • 阴阳量比 • 吸筹
- **⑤ 趋势动量（10个）：** MA5/10/20/60斜率 • RSI(6/14) • MACD • ADX
- **⑥ 市场环境（9个）：** 大盘5/20日收益 • 市场宽度 • 量比 • 波动率 • 回撤
- **⑦ 价格动量（8个）：** 短中期收益 • 最大回撤 • 跳空 • 连涨天数 • 距均线
- **⑧ 板块+基本面（15个）：** 行业涨跌 • 板块宽度 • ROE • PE • PB • 毛利率
- **⑨ 交互特征（3个）：** 振幅×量比 • 紧密度×前高年龄 • 跳空×连涨

**关键原则：** 所有特征只用突破日及以前的数据计算。纯 Python + NumPy + Pandas，不依赖任何预训练模型。你看到的每一个特征，背后都对应着你"看图"时会关注的一个维度。

### 模型训练
**LightGBM：表格数据上的"王者"，快、稳、可解释**
不追求最复杂的模型。追求最能泛化、最快训练、最易解释的模型。

**为什么选 LightGBM?**
- **训练极快：** 几千样本秒级完成，迭代实验成本低
- **天然处理缺失值：** 不需要精细的数据清洗和归一化
- **特征重要性可解释：** 训练完就知道哪些特征贡献最大
- **参数少、防过拟合：** L1/L2 正则化 + 早停机制
- **表格数据 SOTA：** 大量 Kaggle 冠军方案的首选

**训练配置**
- `num_leaves=63 · lr=0.03 · 早停30轮`
- 回归目标：`future_return` (突破后预期收益率%)
- 比二分类（涨/跌）更实用——能按预期收益大小精确排序。

**评估体系不止看一个数字：**
- **Spearman 秩相关**——衡量排序能力，实战最关心的指标
- **Top 5%/10%/20% 平均收益**——模拟真实选前几名
- **Top K 胜率**——选出来的有多少真的涨了
- **RMSE / MAE**——基础误差指标

**部署与避坑：**
- **训练完成后：** 模型保存为 .pkl 文件 → 部署到选股系统的 scorer.py → 每次筛选完自动对候选池打分排序。
- 训练集的夏普 ÷ 测试集的夏普 > 2？严重过拟合。好模型在两段的表[现接近]。

### 总结
**ML 在选股中的正确打开方式**
**核心流程：**
**规则** (逻辑条件筛选，保证候选池，质量下限) ➡️ **5~15只候选** (全部满足，严格条件) ➡️ **ML** (LightGBM 评分，按预期收益率，优中选优)

🔑 **三个核心认知：**
1. **先规则，后 ML。** 逻辑规则保证下限——选出来的每只股票都满足你定义的条件。ML 在此基础上排优先级。这个顺序不能反。
2. **特征工程是灵魂。** 70 个特征 = 把你"看图"的经验数字化。模型好不好，八成看特征，两成看参数。
3. **时间分割，不是随机分割。** 金融数据有时序依赖。随机分割会导致隐式的未来数据泄露，让回测看起来很好、实盘一塌糊涂。

📦 **完整技术栈：**
- 模型训练 → LightGBM (回归)
- 模型部署 → pickle → scorer.py → API
- 评估指标 → Spearman + TopK + 夏普
💡 **机器学习不是魔法。它是在你定义的规则之上，帮你从历史中学习"什么样的突破更容易成功"。**
